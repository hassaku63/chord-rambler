# 文書の鮮度

決定は ADR-0002。ここは書き方の規約と手順。

## 書き方の規約

- **現在の状態だけを書く。** 「以前は」「この PR で」「今回」は書かない。経緯は git log と ADR、検討の過程は Issue。
- **事実は 1 箇所。** 同じ表や数値を 2 箇所に書かず、リンクか、取得するコマンドを書く。
- **将来のことは Issue で指す。** 「〜予定」「後で〜する」を文書に書かない。
- **リポジトリのパスはバッククォートで囲む。** `docs/dev/workflow.md` のように書くと、検査が存在を確かめる。プレースホルダは `<name>` や `*` を含める。
- **音楽の語は、`docs/glossary.md` の「訳語の方針」に従う。** 英語の直訳ではなく定まった日本語の語を使い、英語を見失いやすい語は最初に出たところで英語を括弧で添える。新しい語は先に用語集に足す。
- **`docs/` に文書を足したら索引に載せる。** `docs/README.md`（ADR は `docs/architecture/adr/README.md`）。

## 機械的な検査

`make docs-check`（`scripts/check-docs.sh`）が落とすもの:

| 検査 | 落ちる例 |
| --- | --- |
| 相対リンク | 移動・削除したファイルへのリンク |
| バッククォートのパス | 存在しないファイルやディレクトリ（リポジトリの最上位のディレクトリで始まるもの） |
| 索引 | `docs/` にあるのに索引にない文書 |
| 指示書の行数 | `AGENTS.md` か `CLAUDE.md` が 150 行を超える |
| 競合マーカー | マージで残った `<<<<<<<` |

検査を黙らせるためにパスをバッククォートから外さない。落ちたら文書を現状に合わせる。指摘が誤検知なら、スクリプトの方を直す。

## 自己点検 `docs-sync`（PR を出す前に毎回）

1. 差分を取る: `git diff main...HEAD --stat` と `git diff main...HEAD`。
2. 差分から、言及されうる名前を拾う: 追加・削除・改名した型、関数、ファイル、ディレクトリ、コマンド、設定。
3. それぞれを文書から逆引きする:
   ```bash
   grep -rn --include='*.md' -e '<name>' docs AGENTS.md README.md CLAUDE.md .github
   ```
4. 当たった箇所ごとに判定する: 現状と一致するなら何もしない。古いなら直す。経緯の説明になっているなら削って現在形にする。
5. `make docs-check` を通す。
6. PR 本文の「確認したこと」にチェックを入れる。

## よくある腐り方と対処

| 症状 | 対処 |
| --- | --- |
| 「〜予定」「後で〜する」 | Issue にして、文書からは消す |
| 数値（行数、件数、カバレッジ） | 削って、取得するコマンドを書く |
| 「この PR で」「今回」 | PR 本文に移し、文書は現在形にする |
| 同じ表が 2 箇所にある | 片方を削り、リンクにする |
| ADR に「現在の実装は〜」 | ADR は決定時点の記録。現在の状態はほかの文書に書く |

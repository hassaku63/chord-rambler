# 0014. 小さく、決まった判断に従うだけの PR は、エージェントがマージしてよい

- 日付: 2026-11-15
- 状態: Accepted（所有者の指示。セッションでの回答）

## 文脈

PR のマージは、所有者の OK を待っていた。決まった判断を文書やスキルにするだけの小さな PR でも、OK を待つあいだ次の作業が止まり、未マージの PR の上限（ADR-0013）にも早く届く。

所有者は、差分が小さいものや、全体に影響しない話なら、エージェントがマージしてよいと指示した。セッションをまたいで同じ線で判断できるように、線を文書にする。

## 決定

1. **エージェントが自分で開いた PR は、次のすべてを満たせば、エージェントがマージしてよい。** CI の必須のチェックが緑。新しい判断を含まず、ADR・Issue のコメントの所有者の判断・`docs/` の規則で決まっていることを形にするだけ。下の 2 に当たらない。
2. **次のどれかに当たる PR は、所有者の OK を待つ。**
   - ADR を足す・変える、または所有者の判断を新しく要する。
   - 検査、CI、依存、ビルドとコンテナ、API の契約を変える。
   - 音楽理論の立場（流儀）や、説明の文の規則を変える。
   - 別のセッションや人が開いた PR。
   - 差分が、lockfile と生成物を除いて 600 行を超える（#7 で決めた、PR の大きさの警告の線）。
   - 当たるかどうか迷う。
3. **マージしたら、PR にエージェントがマージしたことと、1 に当たる理由を 1 行で書く。**

線の本体は `docs/dev/workflow.md` の「マージ」に書く。

## 検討した選択肢

- **行数だけで線を引く**: 機械で判定できる。小さくても方針を変える PR（ガードレールの 1 行）を通してしまう。
- **これまでどおり所有者がすべてマージする**: 誤ったマージがない。決まった判断を形にするだけの PR でも作業が止まる。
- **CI が緑ならすべてマージする**: 最も速い。所有者の判断の要る変更が、レビューなしで入る。

## 結果

- 決まった判断を形にするだけの PR では、所有者を待たずに次へ進める。
- 迷ったら待つので、線の近くの PR では所有者を待つ。
- エージェントのマージが正しかったかは、PR に書いた 1 行で、あとから確かめられる。
- 再検討の条件: エージェントがマージした PR を、所有者が戻したり直したりしたとき。

# 0011. 段階ごとにモデルを使い分け、`ready` の Issue を引き継ぎの文書にする

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

検討や調査が重い企画の段階には高価なモデルを使い、目的とやり方が決まったあとの実装には比較的安価なモデルを使いたい（所有者の要望、#30）。強制ではなく、そうなるように誘導したい。

- Claude Code の助言役（advisor）は、主のモデルが作業の要所で、より強いモデルに相談する仕組みで、相談は会話の全体を読む。要所だけで強いモデルを使うので、強いモデルを通しで使うより、ふつうは安い。主が最上位のモデルのときは、費用は下がらない。実験的な機能で、変わりうる（https://code.claude.com/docs/en/advisor.md 、2026-11-15 に確認）。
- サブエージェントは、定義で走るモデルを決められる（https://code.claude.com/docs/en/sub-agents.md ）。
- このリポジトリの作業は、企画（`proposal`）、所有者の判断、`ready` の Issue、実装の順に進む（ADR-0003）。軽いモデルに実装を渡してうまくいくかは、`ready` の Issue に判断が残っていないかで決まる。

## 決定

1. **段階ごとの目安を、`docs/dev/workflow.md` に書く。** 企画・調査・設計は最も強いモデル。`ready` の Issue の実装は一段軽いモデルに強い助言役。定型の作業は軽いモデル。レビューは、実装とは別の強いモデル。モデルの名前ではなく段で書く。強制はしない。
2. **`ready` の Issue は、軽いモデルに渡せる引き継ぎの文書にする。** 書く項目と、`ready` にしない条件を `docs/dev/workflow.md` に置く。判断が残るものは `ready` にせず、企画の Issue に戻す。
3. **助言役の既定は、リポジトリの設定に置かない。** 所有者の個人の設定（`/advisor`）に留める。Fable の利用条件のように、人によって違う設定があるため。
4. **実装用とレビュー用のサブエージェントの定義を、`.claude/agents/` に置く**（別のスライス）。

## 検討した選択肢

- **何も置かず、その都度選ぶ**: 維持の費用がない。段階とモデルの対応が人の記憶に頼り、`ready` の Issue の書き方も揃わない。
- **フックなどで強制する**: 段階とモデルが合わないと止める。所有者の要望（強制ではない）に合わず、実験的な機能に依存した仕組みが壊れやすい。
- **助言役の既定をリポジトリに置く**: クラウドでも手元でも既定で付く。人によって使えるモデルや同意が違い、置いた値が合わない人が出る。

## 結果

- 企画の段階で `ready` の Issue に判断を書き切る手間が増える。その分、実装の段階で迷いと手戻りが減る見込み。
- 費用が実際に下がったかは、セッションごとの使用量で確かめる。数値は文書に書かない。
- 助言役は実験的な機能なので、出どころをプラクティスの索引に入れ、見直しの間隔を短くする。
- 再検討の条件: 軽いモデルに渡した `ready` の Issue で、実装の途中に判断が要って止まることが繰り返されたとき。

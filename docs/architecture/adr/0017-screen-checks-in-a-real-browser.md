# 0017. 画面の通しの操作・アクセシビリティ・配置を、Playwright と axe-core で実ブラウザで検査する

- 日付: 2026-11-16
- 状態: Accepted

## 文脈

部品の単位のテスト（Vitest と Testing Library、jsdom）は、通しの操作の退行（足す → 候補から選ぶ → 鳴らす）、画面の幅による配置の崩れ、アクセシビリティの違反を見つけられない。jsdom は配置を計算せず、`AudioContext` を持たない。#9 で、これらを PR ごとに Chromium で検査すると決めた（#9 のコメント）。実ブラウザを動かす道具は依存なので、ADR を書く（ADR-0009）。

検査は `make check` に入れる（ADR-0004）。手元と CI で同じコマンドが走り、実際の API と画面の開発サーバーを相手にする。

## 決定

1. **開発の依存に `@playwright/test` と `@axe-core/playwright` を足す。** 版は固定する（`package.json` に範囲を書かない）。`@playwright/test` は 1.63.0、`@axe-core/playwright` は 4.14.0（axe-core 4.14.0 を連れてくる）。どちらも入れた日の 2 週間以上前に出た版。Playwright は版ごとに使う Chromium の版が決まっているので、範囲で上がるとブラウザの取り直しが要る。上げるのは Dependabot の PR で、ブラウザと一緒に確かめる。
2. **ブラウザは Chromium だけ。** Playwright の版が決める Chromium を `npx playwright install chromium` で取る。CI は `make check` の前に `--with-deps` を付けて取る。手元で取れないときは、手元にある Chromium の実行ファイルを `PW_CHROMIUM_PATH` で渡せる（`frontend/playwright.config.ts`）。Firefox と WebKit は今は走らせない（#9 のコメント）。
3. **`make e2e` を `make check` に入れる。** API をビルドし、Playwright の `webServer` が API と Vite の開発サーバーを専用のポートで起動する。手元の開発サーバー（8080、5173）は使い回さない。
4. **検査は 3 種類。** 置き場所は `frontend/e2e/`。
   - 通しのシナリオ: 和音名で C を足す、候補から G7 を足す、「進行を鳴らす」で鳴っている枠の印が進む。`AudioContext` は差し替えない（ヘッドレスの Chromium は音の装置なしで作れる。それを確かめるテストを置く）。
   - アクセシビリティ: 空の進行、枠を選んだ状態、候補を開いた状態で、axe-core の WCAG 2.0・2.1・2.2 の A と AA のタグの規則に違反がない。違反は規則を外さずに画面を直す。
   - 配置: 幅 360・768・1280 で、ページが横にスクロールせず、主な操作（調、和音名、再生、候補の「足す」）が見えて、幅の中に収まる。
5. 問い合わせは、Testing Library と同じく、利用者が見つける手がかり（役割と名前、役割のない要素は文字）で書く。CSS のセレクターで引かない。

## 検討した選択肢

- **Vitest のブラウザのモード**: 道具が Vitest に揃う。部品を 1 つずつ描くのが基本で、実際の API と開発サーバーを起動して通しで操る仕組み（`webServer` にあたるもの）を持たない。実ブラウザを動かすには、結局 Playwright か WebdriverIO を足す。
- **Cypress**: 通しのテストの道具として広く使われる。ブラウザの中でテストを走らせる仕組みで、コマンドの連鎖による待ち方が独特で、async と await で書けない。サーバーの起動は道具の外（別の依存か、スクリプト）に置くことになる。axe-core の結びつけは、axe-core の作者のものではない別の依存（cypress-axe）になる。
- **手で確かめる**: 依存が増えない。変更のたびに人が同じ操作を繰り返すことになり、エージェントの PR では確かめられない。ADR-0004 の「機械で検出できるものは機械で」に合わない。
- **axe-core を直接読み込んで `page.evaluate` で走らせる**: `@axe-core/playwright` が要らない。注入とタグの指定、iframe の扱いを自分で書くことになる。依存 1 つで済むなら、公式の結びつけを使う。

## 結果

- 通しの操作、配置、機械で見えるアクセシビリティの違反を、PR ごとに見つけられる。
- `make check` に Chromium が要る。手元にないときの手順は `docs/dev/harness.md`。`make check` は API のビルドと 2 つのサーバーの起動のぶん遅くなる。
- axe-core が見るのは機械で判定できる部分だけ。キーボードで操作が完結するか、読み上げで意味が通るかは、別に確かめる。
- 再検討の条件: 全ブラウザでの実行を足すとき（週次の別の検査として、別の Issue で決める）。`make check` が遅くなって、変更に関係する検査だけを走らせる仕組みが要るとき（ADR-0004 の結果）。

# 0002. 文書は現在の状態だけを書き、機械的な検査で鮮度を保つ

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

エージェントはリポジトリの文書を信じて動くので、古い記述や散らばった経緯は、誤った前提での実装につながる。人力のチェックリストだけでは、文書は時間と規模に負けて腐る。

## 決定

1. **文書は現在の状態だけを書く。** 経緯は git log と ADR に、検討の過程は Issue に残す。
2. **事実は 1 箇所に置き、他は参照する。** 数値・日付・「予定」の一覧をコピーしない。将来のことは Issue で指す。
3. **決定論的な検査を `make check` に組み込む。** リンク切れ、存在しないパス、索引漏れ、指示書の行数、競合マーカー（`scripts/check-docs.sh`）。
4. **PR の前に自己点検をする。** 差分から文書を逆引きする手順（`docs/dev/docs-hygiene.md`）を PR テンプレートの確認項目にする。

## 検討した選択肢

- **規則と PR テンプレートだけ**: 費用はないが、守られたかを誰も検証できない。
- **LLM による PR ごとの監査**: 意味のずれを拾えるが、鍵と費用が要り、誤検知の扱いも決める必要がある。まず構造的に壊れた参照を決定論的に落とす。
- **文書をコードから生成する**: 生成元になるコードがまだない。

## 結果

存在しないパスやリンクを指す文書はマージできない。「予定」や数値を書けないので文書は短くなり、Issue の役割が重くなる。検査は書き方（バッククォートで囲んだパス）に依存するので、その規約を `docs/dev/docs-hygiene.md` に書く。再検討の条件: 検査で拾えない意味のずれが繰り返し見つかったら、定期の点検か LLM の監査を検討する。

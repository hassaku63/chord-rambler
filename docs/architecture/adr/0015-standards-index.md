# 0015. 業界標準の索引を、プラクティスの索引と分けて置く

- 日付: 2026-11-15
- 状態: Accepted（所有者の判断は #52）

## 文脈

`AGENTS.md` は、ファイル形式・記法・プロトコルを決めるときに、業界標準の一次情報に当たるよう求めている。どの標準がどこにあり、どの場面で当たるべきかの手がかりは、リポジトリになかった（#8）。

- 所有者の別のプロジェクト middy には、業界標準の索引（`hassaku63/middy:.claude/skills/standards/index.md@bfbd6ba`）があり、「コンテナとビルド」の節の 3 項目は、どれも middy に固有でない（#52）。
- プラクティスの索引（ADR-0007）は、機械で検出できない開発の判断のためのもので、項目の形（判断の問い、このプロジェクトの立場、対象の版）が標準には合わない。
- プラクティスの索引には、確認日と間隔による鮮度の仕組みがある（ADR-0007、`docs/dev/knowledge-review.md`）。middy の標準の索引は、確認日だけを持つ。

## 決定

1. **業界標準の索引を、`.claude/skills/standards/` に置く。** 中身は一次情報の場所と当たるべき場面だけで、仕様の中身は持たない。使い方と項目の形は、その `SKILL.md` に書く。
2. **プラクティスの索引とは分ける。** 開発の判断はプラクティスの索引、ファイル形式・記法・プロトコル・設定ファイルの書き方は標準の索引に置く。
3. **最初の節は「コンテナとビルド」。** middy の 3 項目を、一次情報を開き直し、chord-rambler との接点に書き直して入れる。ほかの分野（和音の表記、MIDI、譜面の形式など）は、エンジンのスライスで足す。
4. **鮮度は、プラクティスの索引と同じ形で見る。** `確認` の欄を `YYYY-MM-DD / 間隔 N 日` にし、項目の形の検査と、期限の報告を、今ある仕組みに足す（別のスライス）。

## 検討した選択肢

- **プラクティスの索引に入れる**: 仕組みはもうある。項目の形が合わず、標準の項目に「判断の問い」を無理に書くことになる。
- **取り込まない**: 維持するものが増えない。必要になるたびに一次情報を探し直す。
- **確認日だけにする**（middy と同じ）: 仕組みが小さい。古くなったことに、四半期の総点検でしか気づけない。

## 結果

- Dockerfile や `compose.yaml` を変えるとき、正しい一次情報と、要る最小の版に早く当たれる。
- 見直す索引が 2 つになる。期限の報告が両方を見るので、手間の増え方は項目の数に比例する。
- middy の索引とは別に保つ。同じ標準の項目でも、確認と接点はそれぞれのリポジトリで持つ。
- 再検討の条件: 2 つの索引の境目に置き場所の決まらない項目が繰り返し出てきたとき。

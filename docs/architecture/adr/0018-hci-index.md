# 0018. HCI の知見の索引を、標準とプラクティスの索引の隣に置く

- 日付: 2026-11-18
- 状態: Accepted（所有者の判断は #176）

## 文脈

今の画面は仮の配置で、画面の構成の企画（`docs/product/concept.md` の 8 章）で作り直す（`docs/architecture/screen.md`）。構成や状態の見せ方を決めるときに、画面・操作・フィードバック・配色についての知見を引く場所が、リポジトリになかった（#176）。

- 所有者の別のプロジェクト middy には、HCI の知見の索引（`hassaku63/middy:.claude/skills/hci/index.md@bfbd6ba`。35 項目と、外したもの）がある。項目は、出典、何を言っているか、確からしさ、当たるべき場面、判断の問い、例、middy との接点、確認日を持つ。
- middy の項目の多くは、原論文を開けず、NN/g や W3C の解説で確かめたもの。この repository の環境で開けるサイトは、middy のときと同じではない。
- 業界標準の索引（ADR-0015）は、middy から移すときに一次情報を開き直した。プラクティスの索引と標準の索引は、確認日と間隔で鮮度を見る（ADR-0007）。
- 標準の索引には、WCAG 2.2 そのものの項目がある。

所有者は #176 で、middy の HCI の索引をもとにし、項目ごとに一次情報を開き直してから移すと決めた（#189）。

## 決定

1. **HCI の知見の索引を `.claude/skills/hci/` に置く。** 研究の本文は持たず、要点・確からしさ・一次情報の場所・判断の問いだけを持つ。項目は「どの判断を助けるか」で節に分ける。使い方と項目の形は、その `SKILL.md` に書く。
2. **3 つの索引の分担。** 開発の判断はプラクティスの索引、仕様と一次情報の場所は標準の索引（WCAG 2.2 そのものも）、画面と操作の判断の根拠は HCI の索引に置く。HCI の索引は、WCAG の個々の達成基準を、画面の判断の根拠として引いてよい。
3. **middy の形を保ち、2 点だけ変える。**
   - 「middy との接点」を「chord-rambler との接点」にし、今の画面とコンセプトに照らして書き直す。当たるべき場面、判断の問い、例も、chord-rambler の画面の語で書き直す。
   - 「確認日」を `YYYY-MM-DD / 間隔 N 日（開いたもの）` の形にする。間隔は 365 日。期限の報告（`scripts/knowledge-staleness.sh`）が、ほかの 2 つの索引と同じに期限を見られるようにするため。どれも開けなかった項目は `未確認（理由）` とし、期限を持たないので、総点検（`docs/dev/knowledge-review.md`）で開き直す。
4. **移すときに開き直す。** 項目に書いた一次情報か、権威ある公開資料（W3C、MDN、NN/g など）を開き、開いたものに書かれていることだけを書く。開けなかった原論文は名前だけを残し、中身は書かない。開いたサイトと開けなかったサイトを、索引の冒頭に書く。
5. **chord-rambler に関係が薄い項目と、開けた資料で中身を支えられない部分は「外したもの」に理由と一緒に置く。** 会話型の AI の UI は、生成 AI を使わない最初の範囲（`docs/product/concept.md` の 10 章）では関係が薄い。
6. **形を `make check` で検査する**（`scripts/check-hci.sh`）。欄の欠けと空、出典の URL、確認日の書き方、40 項目の上限。
7. **画面・操作・フィードバック・配置・色を決める・変えるときは索引を引き、判断の問いへの答えを PR の「当たった索引の項目」に書く**（`AGENTS.md` の 3 章）。
8. **PR の大きさの予算に収まらないときは、2 回に分けて移す。** 先に、今の画面に効く節（何を同時に見せるか、状態とモード、操作の対象と手がかり、待ちと応答、支援技術）と仕組みを入れる。

## 検討した選択肢

- **middy の索引をそのまま写す**: 速い。この環境で開けていない中身を、確かめたものとして持つことになる。
- **標準の索引かプラクティスの索引に入れる**: 仕組みはもうある。項目の形（標準は一次情報の場所、プラクティスは対象の版）が合わない。
- **確認日を middy と同じく日付だけにする**: 形が middy と同じになる。期限の報告に載せるには、項目ごとに間隔を決める別の規則が要る。
- **取り込まない**: 維持するものが増えない。画面の構成を決めるたびに、知見を探し直す。

## 結果

- 画面の構成の企画で、配置・状態・手がかり・待ち・支援技術の判断に、確かめた根拠と問いを当てられる。
- 見直す索引が 3 つになる。期限の報告と総点検の手間は、項目の数に比例して増える。
- middy の索引とは別に保つ。同じ知見の項目でも、確認と接点はそれぞれのリポジトリで持つ。
- 原論文を開けない項目は、解説の範囲でしか書けない。網の方針が変わって開けるようになったら、総点検で足す。
- 再検討の条件: 3 つの索引の境目に置き場所の決まらない項目が繰り返し出てきたとき。索引が PR で引かれないまま、総点検で削る候補ばかりになったとき。

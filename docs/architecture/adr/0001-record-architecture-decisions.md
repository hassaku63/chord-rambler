# 0001. 設計判断を ADR に記録する

- 日付: 2026-11-15
- 状態: Accepted

## 文脈

chord-rambler は、人間と AI エージェントがセッションをまたいで開発する。エージェントは記憶を持たず、リポジトリの文書を信じて動く。「なぜそうなっているか」が残っていないと、同じ検討を繰り返すか、理由を知らずに決定を覆す。

## 決定

設計判断（技術スタック、依存の追加、データモデル、責務の境界、開発の規則）は、`docs/architecture/adr/` に 1 判断 1 枚で記録する。形式は `0000-template.md`（文脈、決定、検討した選択肢、結果）。

- 番号は連番。索引（`README.md`）に載せる。
- ADR は決定時点の記録で、本文を書き換えない。改めるときは新しい ADR を足し、古い方を `Superseded by NNNN` にして、影響する現在の文書を同じ PR で直す。
- 現在の状態は ADR ではなく、それを説明する文書（`docs/` のほかの文書）に書く。

## 検討した選択肢

- **Issue と PR の本文だけに残す**: 追加の文書が要らないが、決定が検討の過程に埋もれ、リポジトリだけを読むエージェントから見えない。
- **1 つの設計文書に追記する**: 現在の状態と経緯が混ざり、文書が長くなる。

## 結果

決定の理由がリポジトリの中で引ける。判断のたびに 1 枚書く手間が増える。小さな判断まで ADR にすると索引が読まれなくなるので、あとから覆すと手戻りが大きい判断に限る。

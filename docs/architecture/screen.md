# 画面の構成

画面は React と TypeScript で作り、エンジンの API を呼ぶ（ADR-0008）。ここは今の画面の構成。

## 仮の配置

今の配置は仮のもの（#148 の A1）。2 つの体験を 1 つの画面にまとめるか、分けるかは、構成の企画（`docs/product/concept.md` の 8 章）で決め、配置もそこで作り直す。

画面 1 は、進行を組み、読みの札を見る。画面 2 は、それを鳴らす。画面 3 は、末尾の次の和音を候補から選んで足し、変形で彩る（体験 A）。画面 4 は、枠に役割を置き、選んだ枠を役割に合う候補で埋める（体験 B）。上から次の順に並ぶ。

1. 調の選択（12 の長調。既定は C）。再生の操作（下の「鳴らし方」）。和音名の入力と、枠を足す操作。打った和音の枠の長さは、候補と同じ規則で決める（下の「候補」）。和音のない枠と、まだ選んでいない枠も、同じ規則で長さを決める。
2. 枠の帯。枠を左から右に並べ、折り返す。カードは、和音名・ローマ数字・札の短い印（種別、機能、解決・終止、役割に合うか）と、長さ（1 拍から、その枠の始まりからフレーズの終わりまでの拍の数まで。下の「候補」）・役割（下の「役割」）・消す操作を持つ。鳴っている枠は、カードに「鳴っています」の文字と破線の枠を出し、`aria-current` を付ける。
3. 選んだ枠の詳しい札。種別、機能、借り先、向かう先、解決、終止、テンションの注意、役割に合うかを、語と根拠の種類の印で出す。文にはしない（#110 の B1）。その下に、選んだ枠の変形（下の「変形」）と、選んだ枠を埋める候補（下の「枠を埋める候補」）。
4. 末尾に足す候補（下の「候補」）。

## 置き場所

| 場所 | 中身 |
| --- | --- |
| `frontend/src/features/progression/useProgression.ts` | 進行の状態と操作。`localStorage` に API の `Progression` と同じ形（枠の役割を含む）で残し、読み出した値は境界で検証する（壊れていれば空の進行。知らない役割も壊れた値とみる）。枠ごとの変形の土台も、枠と同じ状態に持つ（残さない）。末尾に足す枠の長さ（`nextBeats`）と、枠の長さの上限（`maxBeatsAt`）を決める |
| `frontend/src/features/progression/useVariations.ts` | 選んだ枠の土台が変わるたびに `POST /variations` を呼ぶ。古い応答は捨てる |
| `frontend/src/features/progression/useProgressionReading.ts` | 進行が変わるたびに `POST /progressions/readings` を呼ぶ。古い応答は捨てる |
| `frontend/src/features/progression/usePlayback.ts` | 進行が変わるたびに `POST /progressions/notes` を呼び（古い応答は捨てる）、テンポを持ち、進行の全体か 1 枠を鳴らす。候補の試聴も、ここから鳴らす。試聴中の候補は、和音名と、試す枠の位置で持つ |
| `frontend/src/features/progression/useNextCandidates.ts` | 進行が変わるたびに、`nextBeats` の長さで `POST /progressions/next-candidates` を呼ぶ。古い応答は捨てる。新しい応答を待つあいだは、前の答えを返し、待っていることを知らせる |
| `frontend/src/features/progression/useSlotCandidates.ts` | 選んだ枠（まだ選んでいない枠か、和音のある枠）か進行が変わるたびに、`POST /progressions/slot-candidates` を呼ぶ。古い応答は捨てる。新しい応答を待つあいだは、同じ枠への前の答えだけを返す |
| `frontend/src/features/progression/CandidateList.tsx` | 候補の一覧。末尾に足す候補と枠を埋める候補が、語（見出し、一覧の名前、ボタン）と、印と札の関数を変えて共有する |
| `frontend/src/features/progression/schedule.ts` | 音符を発振器の予定（周波数、始まりの秒、長さ、音量）に直す純粋な関数 |
| `frontend/src/features/progression/usePlayer.ts` | Web Audio で予定を鳴らす。`AudioContext` を作る関数を引数で受ける（テストは `frontend/src/test/fakeAudioContext.ts` を渡す） |
| `frontend/src/features/progression/terms.ts` | 札と役割の識別子を語にする表。ここ 1 か所に置く。役割の一覧も、ここの表から引く |
| `frontend/src/shared/api/client.ts` | API の呼び出しと、応答の検証 |
| `frontend/e2e/` | 実ブラウザでの画面の検査（ADR-0017）。通しのシナリオ（`progression.spec.ts`）、アクセシビリティ（`accessibility.spec.ts`）、配置（`layout.spec.ts`）。画面の語や操作を変えたら、ここの問い合わせも直す |

## 札の語

- 語は `docs/glossary.md` の語だけを使う。
- 契約が「名付けるものがない」とする値（`none`、`facts-only`）は、札を出さない。
- 表にない識別子は、表示を落とさずに識別子のまま出す。
- テンションの注意の音程は、契約の書き方（`P11`、`M3`）のまま出す。

## 役割

- 枠のカードの「役割」の `select` で、なし、構造的な役割の 6 つ、色合いの役割の 4 つ（語は `docs/glossary.md`）から選ぶ。種類ごとに `optgroup` でまとめる。
- 役割は枠の一部として、`localStorage` と API に送る `Progression` に入る。なしの枠は `role` の欄を持たない。長さを変えても、和音を置き換えても、役割は残る。
- 役割に合うか（合う、合わない、決められない）は、読みの `roleFit` をそのまま出す。カードには「役割に合うか 合わない」の形の印で、詳しい札には「役割に合うか」の行で出す。役割なしと色合いの役割の枠には、読みが何も言わないので、何も出さない（`docs/architecture/theory-conventions.md` の 7）。
- 読みの `roleFit` は「合わない」の理由を持たないので、カードと詳しい札には理由を出さない。

## 候補

- 足す枠の長さは 1 小節（4 拍）。満ちていないフレーズ（4 小節、16 拍）の残りがそれより短いときは、残りの拍にする。問い合わせにも、「足す」で足す枠にも、和音名を打って足す枠にも、和音なしとまだ選んでいない枠にも、この長さを使う。枠の「長さ」の選択肢は、1 拍からその枠の始まりのフレーズの終わりまでで、フレーズをまたぐ長さは出さない（API が 400 を返すため。フレーズの拍の数は `PHRASE_BEATS` の 1 か所）。丸めたことは知らせない。足した枠のカードに長さが見える。
- 候補は、まとまり（ダイアトニック、セカンダリー・ドミナント、借用和音）ごとに `details` 要素で出す。初めはダイアトニックだけを開いておく（#112 の C1）。開け閉めは、まとまりの種別ごとに画面が覚え、答えが変わっても保つ。まとまりの名前が、候補の種別の印を兼ねる。
- 進行が変わって新しい候補を待つあいだも、前の答えの一覧を出したままにする。待っていることは、区画の `aria-busy` と「新しい候補を待っています。」の文で示す。文の行はいつも場所を取り、出し入れで一覧が動かない。待つあいだは前の一覧の「足す」と「この枠に入れる」を押せなくし（同じ候補が二重に足されない）、試聴は押せる。
- 「足す」を押すと、フォーカスを区画の見出しに移す。待つあいだ区画は外れないので、フォーカスはページに落ちない。
- 各候補は、和音名、ローマ数字、短い印（機能、根音の動き、共通音の数、末尾の和音の解決、終止、好み）を出す。詳しい札は、候補ごとの `details` 要素で開いて見る。
- 好みは、様式の範囲と一緒に出す（「クラシックでは、より少ない」。#114）。詳しい札では、機能の動き（サブドミナント → ドミナント）も添える。好みは和音ではなく、機能の動きのものだから。
- 操作は「足す」（末尾に足す）と「試聴」。試聴は、候補を足した進行の音符を問い合わせ、末尾の枠（和音があるとき）と候補を続けて鳴らす。鳴らすのは画面 2 と同じ音の hook。試聴中のボタンは `aria-pressed` で示し、もう一度押すと止まる。試聴中の候補には「試聴中」の文字と破線の枠を出し、`aria-current` を付ける。
- 候補を得られない（拒まれた、つながらない）あいだは、候補を出さない。理由は読みの側で出す。

## 枠を埋める候補

- まだ選んでいない枠か、和音のある枠を選ぶと、その枠の候補を出す。和音なしの枠では出さない。
- 一覧の部品、まとまりと並び、開け閉め、待つあいだの示し方、フォーカスは、末尾に足す候補（上の「候補」）と同じ。並びはサーバーの順のまま（各まとまりで、役割に合う候補が先）。見出しは「選んだ枠を埋める候補（4 拍）」、一覧の名前は「この枠のダイアトニックの候補」の形にし、末尾に足す候補と区別する。
- 短い印は、末尾に足す候補の印に、次の枠への解決（「次の枠へ 解決」）、次の枠の終止（「次の枠 正格終止」）、役割に合うかを足す。詳しい札では、前の枠の和音の解決、次の枠への解決、次の枠の終止、役割に合うか、合わない理由を出す。合わない理由は、当たらなかった条件を `docs/architecture/theory-conventions.md` の 7 の表の語で、表の順に並べる。役割なしと色合いの役割の枠では、サーバーが役割に合うかを返さないので、出さない。色合いの役割で候補を絞らない（#124 の C1）。
- 操作は「この枠に入れる」と「試聴」。「この枠に入れる」は、枠の中身だけを候補の和音に替え、長さと役割は保つ。入れた和音は、末尾に足した候補と同じく、その枠の変形の土台になる。試聴は、候補を枠に入れた進行の音符を問い合わせ、前の枠・候補・次の枠を続けて鳴らす。前後の枠は、和音があるときだけ鳴らす。試聴中の示し方は、末尾に足す候補と同じ。

## 変形

- 和音のある枠を選ぶと、その枠の土台の変形を出す。選ぶと、その枠の和音を置き換える。長さと土台は保つ。今の和音のボタンは `aria-pressed` で示す。
- 土台は、候補から足した枠では、足したときの和音（#115 の所有者の判断 2）。sus を選んだあとも、土台から一覧を出し直せる。ほかの枠では、今の和音。
- 土台は画面の状態にだけ持ち、`localStorage` には残さない。読み込み直すと、どの枠も今の和音が土台になる。
- 3 度のない和音（打った sus など）は、API が断る。断られたら一覧を出さない。警告も出さない。

## 読みの失敗

API の problem の `detail` を、`role="alert"` でそのまま出す。問題が 1 つの枠にあるとき、problem は `slot` の欄（0 から数える）を持ち、その枠のカードにも印を付ける。`slot` の欄がなければ、`detail` の文が枠を名指すとき（`slot 2: ...`）の番号を使う。

## 鳴らし方

音は Web Audio API で直接鳴らす（ADR-0008 の 7）。エンジンは拍で数えた音符を返し、拍を秒に直すのは画面の側。

- 操作は「進行を鳴らす」（先頭から最後まで）、「この枠だけ鳴らす」（選んだ枠の音符だけを、その枠の長さで）、「止める」、テンポのスライダー。
- 再生中のボタンは `aria-pressed` で示す。押されているボタンをもう一度押すと止まる。
- テンポは 40〜200 BPM、既定は 90。変えたテンポは次の再生から効く。進行が変わると、再生は止まる。
- 音の高さは、MIDI のノート番号から平均律で求める（A4 = 69 = 440 Hz）。強さ（0〜127）は音量に写す。
- 音色は 1 つ。三角波に、短い立ち上がりと終わりまでの減衰を付ける。和音の声部が重なっても割れないよう、全体の音量を下げて出す。数値は `usePlayer.ts` の定数。
- `AudioContext` は最初の操作で作り、止まっていれば再開する（ブラウザの自動再生の制限のため）。
- 音符を得られない（拒まれた、つながらない）あいだ、和音のない枠を選んだときは、鳴らすボタンを押せない。理由は読みの失敗と同じなので、読みの側で出す。

# 画面の構成

画面は React と TypeScript で作り、エンジンの API を呼ぶ（ADR-0008）。ここは今の画面の構成。

## 配置

画面は、目標の画面（ADR-0019。約束は `docs/product/screen-promise.md`）の骨組みのうち、キャンバス・帯・文脈の欄と 2 つのタブまでを持つ。探索のタブの枝と探索の足跡（約束の 4 の点 1・3。下の「枝」）を持つ。枝の一言、計画のタブの流れ、元に戻す、移調はまだない。幅 1000 px 以上では画面を窓の高さに収め、3 つの区画がスクロールなしで同時に見える。あふれる分は区画の中でスクロールする。狭い幅では縦に積む。色は `frontend/src/app/app.css` の `:root` のトークン（クリーム地と深緑）にまとめる。

- 上: 調の選択（12 の長調。既定は C）。調を変えると、和音名はそのままで読み直す。和音名の入力と、枠を足す操作。打った和音の枠の長さは、候補と同じ規則で決める（下の「候補」）。和音のない枠と、まだ選んでいない枠も、同じ規則で長さを決める。探索のタブと計画のタブ（`role="tablist"`。矢印のキーで移る）。選んでいるタブは塗りと太字で示し、文脈の欄の最初の行にも「探索のタブ」の形で出す。タブを切り替えても、進行は変わらない。
- 左上: キャンバス（見出し「流れ」）。枠ごとの本線のノードを左から並べる。ノードは、何番目か、和音名（大きく、セリフ体）、ローマ数字を持ち、和音のない枠とまだ選んでいない枠は語で出す。押すと、その枠を選ぶ（帯の枠と同じ選び。もう一度押すと外す）。ノードのあいだの矢印の上に、前の枠の解決（読みの解決は、その枠から次の枠への判定）と後ろの枠の終止を、語ごとの小さな札で載せる（札は折り返さない）。何も述べない判定は載せない。鳴っているノードは、「鳴っています」の文字と破線の枠で示し、`aria-current` を付ける。探索のタブでは、末尾のノード（枠がなければ「始まり」の印）から枝を伸ばし、探索の足跡を、確定したノードの下に出す（下の「枝」）。
- 左下: 帯（見出し「時間と再生」）。枠を時間の順に、拍の数に比例した幅で並べる（1 拍の枠だけは、操作が収まる幅まで広げる）。はみ出す分は帯の中で横にスクロールする。枠の中に、そこで始まる小節の目盛り（「小節 2」）とフレーズの区切り（「フレーズ 2」。太い線と語）を出す。枠は、和音名・ローマ数字・札の短い印（種別、機能、解決・終止、役割に合うか）と、長さ（1 拍から、その枠の始まりからフレーズの終わりまでの拍の数まで。下の「候補」）・役割（下の「役割」）・消す操作を持つ。鳴っている枠は、「鳴っています」の文字と破線の枠を出し、`aria-current` を付ける。読みの失敗、再生の操作（下の「鳴らし方」）、枠を縮めたことを知らせる 1 行（下の「フレーズをまたがない」）も帯に置く。
- 右: 文脈の欄。タブと、選んでいる枠（和音名と何番目の枠か。選んでいなければ「枠を選んでいません」）をいつも出す。枠を選んでいるときは、その枠の詳しい札（種別、機能、借り先、向かう先、解決、終止、テンションの注意、調の外の音、役割に合うかを、語と根拠の種類の印で出す。文にはしない。#110 の B1）と、変形（下の「変形」）。計画のタブでは、加えて選んだ枠を埋める候補（下の「枠を埋める候補」）を出し、何も選んでいなければ枠を選ぶよう促す。探索のタブで枝を選んでいるときは、その枝（「F（2 番目の枠の枝）」の形）の短い印と詳しい札と、確定する操作を出す。探索のタブで枠を選んでいないときは、末尾に足す候補（下の「候補」）の全部を、枝にしたものも含めて「他の候補（末尾に足す、4 拍）」の見出しで出す。

## 札の語

- 語は `docs/glossary.md` の語だけを使う。
- 契約が「名付けるものがない」とする値（`none`、`facts-only`）は、札を出さない。
- 表にない識別子は、表示を落とさずに識別子のまま出す。
- テンションの注意の音程は、契約の書き方（`P11`、`M3`）のまま出す。
- 調の外の音は、読みの `outOfKey` の音名を、契約の綴りのまま「、」でつないで出す（「調の外の音 A♭ 〔計算〕」）。読みが持たなければ行を出さない。カードには印を出さない。変形の一覧での出し方は、下の「変形」。

## 役割

- 枠のカードの「役割」の `select` で、なし、構造的な役割の 6 つ、色合いの役割の 4 つ（語は `docs/glossary.md`）から選ぶ。種類ごとに `optgroup` でまとめる。
- 役割は枠の一部として、`localStorage` と API に送る `Progression` に入る。なしの枠は `role` の欄を持たない。長さを変えても、和音を置き換えても、役割は残る。
- 役割に合うか（合う、合わない、決められない）は、読みの `roleFit` をそのまま出す。カードには「役割に合うか 合わない」の形の印で、詳しい札には「役割に合うか」の行で出す。役割なしと色合いの役割の枠には、読みが何も言わないので、何も出さない（`docs/architecture/theory-conventions.md` の 7）。
- 読みの `roleFit` は「合わない」の理由を持たないので、カードと詳しい札には理由を出さない。

## 枝

- 枝は、末尾に足す候補の答えの、まとまりの順の先頭から 5 つ（約束の 5 の暫定。`BRANCH_COUNT`）。先頭はダイアトニックに偏り、C の始まりでは C、Cmaj7、Dm、Dm7、Em になる。#203 が決まるまで、この偏りを残す。一言は出さない（#204）。
- 枝は、和音名（セリフ体）とローマ数字のボタン。枝の組は `role="toolbar"`（名前は「枝」）で、Tab の止まりは 1 つ（選んでいる枝か、最初の枝）。矢印のキーで枝のあいだを移る。Tab の順は、本線のノード、探索の足跡、枝。
- 枝を押すかフォーカスすると、その枝を選び（`aria-pressed`）、末尾の枠と枝を鳴らす（候補の試聴と同じ）。ポインターで押したときは、フォーカスでは鳴らさず、押したことで鳴らす（二重に鳴らさない）。試聴中の枝は、「試聴中」の文字と破線の枠で示し、`aria-current` を付ける。枝を選ぶと枠の選びは外れ、ノードか枠を選ぶと枝の選びは外れる。
- 確定は、枝での Enter、ダブルクリック、文脈の欄の「確定する」。確定すると、枝を末尾に足し（候補から足した枠と同じく、変形の土台になる）、新しい答えが来たら、新しい最初の枝にフォーカスを移す。フォーカスで鳴るので、移った枝も鳴る。新しい答えを待つあいだは、前の答えの枝を出したままにし（`aria-busy`）、押しても何もしない。
- 探索の足跡は、確定した枝の組のうち、選ばなかった枝。確定したノードの下に、薄い語と細い破線で、「探索の足跡」の名前を付けて出す（`role="toolbar"`）。足跡の枝を押すと、前の枠とその枝を鳴らし、確定すると、その位置の和音を置き換える（長さと役割は保つ）。置き換えたあとも足跡は残り、置き換えられた和音が足跡に入る。足跡は 1 歩分だけで、ほかに進行を変える操作をすると消える。計画のタブでは、枝も足跡も出さない。
- 枝が伸びる・足跡が薄れる動きは付けない（`prefers-reduced-motion` によらず、即時に切り替わる）。

## 候補

- 足す枠の長さは 1 小節（4 拍）。満ちていないフレーズ（4 小節、16 拍）の残りがそれより短いときは、残りの拍にする。問い合わせにも、「足す」で足す枠にも、和音名を打って足す枠にも、和音なしとまだ選んでいない枠にも、この長さを使う。枠の「長さ」の選択肢は、1 拍からその枠の始まりのフレーズの終わりまでで、フレーズをまたぐ長さは出さない（API が 400 を返すため。フレーズの拍の数は `PHRASE_BEATS` の 1 か所）。足すときに丸めたことは知らせない。足した枠のカードに長さが見える。
- 候補は、まとまり（ダイアトニック、セカンダリー・ドミナント、借用和音）ごとに `details` 要素で出す。初めはダイアトニックだけを開いておく（#112 の C1）。開け閉めは、まとまりの種別ごとに画面が覚え、答えが変わっても保つ。まとまりの名前が、候補の種別の印を兼ねる。
- 進行が変わって新しい候補を待つあいだも、前の答えの一覧を出したままにする。待っていることは、区画の `aria-busy` と「新しい候補を待っています。」の文で示す。文の行はいつも場所を取り、出し入れで一覧が動かない。待つあいだは前の一覧の「足す」と「この枠に入れる」を押せなくし（同じ候補が二重に足されない）、試聴は押せる。
- 「足す」を押すと、フォーカスを区画の見出しに移す。待つあいだ区画は外れないので、フォーカスはページに落ちない。
- 各候補は、和音名、ローマ数字、短い印（機能、根音の動き、共通音の数、末尾の和音の解決、終止、好み）を出す。詳しい札は、候補ごとの `details` 要素で開いて見る。
- 好みは、様式の範囲と一緒に出す（「クラシックでは、より少ない」。#114）。詳しい札では、機能の動き（サブドミナント → ドミナント）も添える。好みは和音ではなく、機能の動きのものだから。
- 操作は「足す」（末尾に足す）と「試聴」。試聴は、候補を足した進行の音符を問い合わせ、末尾の枠（和音があるとき）と候補を続けて鳴らす。鳴らすのは進行を鳴らすのと同じ音の hook。試聴中のボタンは `aria-pressed` で示し、もう一度押すと止まる。試聴中の候補には「試聴中」の文字と破線の枠を出し、`aria-current` を付ける。
- 候補を得られない（拒まれた、つながらない）あいだは、候補を出さない。理由は読みの側で出す。

## フレーズをまたがない

- 枠を消す、枠の長さを変える（縮める、伸ばす）など、進行を変える操作のたびに、枠を左から順に見る。始まりのフレーズの終わりを越える枠は、そのフレーズの終わりまで縮める（1 拍以上になる）。縮めると後ろの枠の始まりがずれるが、そのずれも同じ 1 回の走査で扱う。読みと候補の問い合わせは、縮めたあとの進行で行う。
- 縮めた枠があれば、帯の中の `role="status"` の行に 1 文で知らせる（「G の枠を 2 拍に縮めました（フレーズをまたぐため）。」）。複数なら「、」でつないで 1 文にする。足すときの丸め（上の「候補」）と違い、利用者が決めた長さを変えるので知らせる。文は、次に進行を変える操作で消える（時間では消えない）。枠を選ぶだけでは消えない。行はいつも場所を取り、出し入れで下が動かない。
- 読み込んだ進行に、またぐ枠が残っていても、読み込んだときには縮めない。最初に進行を変える操作で縮めて知らせる。

## 枠を埋める候補

- まだ選んでいない枠か、和音のある枠を選ぶと、その枠の候補を出す。和音なしの枠では出さない。
- 一覧の部品、まとまりと並び、開け閉め、待つあいだの示し方、フォーカスは、末尾に足す候補（上の「候補」）と同じ。並びはサーバーの順のまま（各まとまりで、役割に合う候補が先）。待つあいだ前の一覧を出したままにするのは、同じ枠を選び続けているあいだだけ。選ぶ枠を替えたときと、選びを外してから選び直したときは、答えが来るまで一覧を出さない（消した枠で番号がずれても、前の枠の候補を出さない）。見出しは「選んだ枠を埋める候補（4 拍）」、一覧の名前は「この枠のダイアトニックの候補」の形にし、末尾に足す候補と区別する。
- 短い印は、末尾に足す候補の印に、次の枠への解決（「次の枠へ 解決」）、次の枠の終止（「次の枠 正格終止」）、役割に合うかを足す。詳しい札では、前の枠の和音の解決、次の枠への解決、次の枠の終止、役割に合うか、合わない理由を出す。合わない理由は、当たらなかった条件を `docs/architecture/theory-conventions.md` の 7 の表の語で、表の順に並べる。役割なしと色合いの役割の枠では、サーバーが役割に合うかを返さないので、出さない。色合いの役割で候補を絞らない（#124 の C1）。
- 操作は「この枠に入れる」と「試聴」。「この枠に入れる」は、枠の中身だけを候補の和音に替え、長さと役割は保つ。入れた和音は、末尾に足した候補と同じく、その枠の変形の土台になる。試聴は、候補を枠に入れた進行の音符を問い合わせ、前の枠・候補・次の枠を続けて鳴らす。前後の枠は、和音があるときだけ鳴らす。試聴中の示し方は、末尾に足す候補と同じ。

## 変形

- 和音のある枠を選ぶと、その枠の土台の変形を出す。選ぶと、その枠の和音を置き換える。長さと土台は保つ。今の和音のボタンは `aria-pressed` で示す。
- 各変形は、和音名のボタンの横に、短い印（種別、機能）と、調の外の音（変形の `outOfKey`）を出す。調の外の音は、詳しい札と同じ語と「、」のつなぎで「調の外の音 A♭、E♭」の形にし、根拠の印は付けない（ほかの印と同じ）。`outOfKey` が空の変形には出さない。印はボタンの名前に入れず、名前は和音名だけにする（候補の印と同じ）。
- 土台は、候補から足した枠では、足したときの和音（#115 の所有者の判断 2）。sus を選んだあとも、土台から一覧を出し直せる。ほかの枠では、今の和音。
- 土台は画面の状態にだけ持ち、`localStorage` には残さない。読み込み直すと、どの枠も今の和音が土台になる。
- 3 度のない和音（打った sus など）は、API が断る。断られたら一覧を出さない。警告も出さない。

## 読みの失敗

API の problem の `detail` を、`role="alert"` でそのまま出す。問題が 1 つの枠にあるとき、problem は `slot` の欄（0 から数える）を持ち、その枠のカードにも印を付ける。`slot` の欄がなければ、`detail` の文が枠を名指すとき（`slot 2: ...`）の番号を使う。

## 鳴らし方

音は Web Audio API で直接鳴らす（ADR-0008 の 7）。エンジンは拍で数えた音符を返し、拍を秒に直すのは画面の側。

- 操作は「進行を鳴らす」（先頭から最後まで）、「この枠だけ鳴らす」（選んだ枠の音符だけを、その枠の長さで）、「止める」、テンポのスライダー。
- 再生中のボタンは `aria-pressed` で示す。押されているボタンをもう一度押すと止まる。
- テンポは 40〜200 BPM、既定は 90。変えたテンポは次の再生から効く。進行が変わると、再生は止まる。
- 音の高さは、MIDI のノート番号から平均律で求める（A4 = 69 = 440 Hz）。強さ（0〜127）は音量に写す。
- 音色は 1 つ。三角波に、短い立ち上がりと終わりまでの減衰を付ける。和音の声部が重なっても割れないよう、全体の音量を下げて出す。数値は `usePlayer.ts` の定数。
- `AudioContext` は最初の操作で作り、止まっていれば再開する（ブラウザの自動再生の制限のため）。
- 音符を得られない（拒まれた、つながらない）あいだ、和音のない枠を選んだときは、鳴らすボタンを押せない。理由は読みの失敗と同じなので、読みの側で出す。

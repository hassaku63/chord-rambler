| 出典 | Harley, A. (2020) Proximity Principle in Visual Design, NN/g https://www.nngroup.com/articles/gestalt-proximity/ 。Harley, A. | 何を言っているか | 近い・似ている（色・形・大きさ）・同じ枠の中にある要素は、ひとまとまりに見える。近接は色や形の類同に勝ちうる。枠（共通領域）は近接や類同に勝ちうる。類同は弱いが、離れた要素を結べる。飾りの枠や色の箱を足すと散らかり、見る負荷が増えるので、余白で足りるなら余白を使う。幅が変わって折り返すと、群が崩れることがある |
| 確からしさ | 原理の存在は長い研究の積み重ねがある（総説は開いていない）。どの原理が勝つかは見た目しだいで、NN/g の記事は実務の観察と作例で述べる |
| 当たるべき場面 | 枠のカードの中の要素（和音名、印、長さ、役割、消す）の並び。候補の一覧で、どの印と操作がどの候補に属するか。区画の区切り。余白・枠・色で群を作るとき |
| 判断の問い | 見た目の近さ・枠・色が、意味の所属（どの枠の札か、どの候補の操作か）と一致しているか。意図しない群（主の操作が従の操作と同じ間隔・重さで並ぶ）ができていないか。狭い幅で折り返したあとも群が保たれるか |
| 適切・不適切な例 | 適切: 1 つの候補の和音名・印・「足す」・「試聴」を 1 つの箱に入れ、隣の候補とは間を空ける。不適切: 候補の間と、候補の中の要素の間が同じ余白で、どの「足す」がどの和音のものか分からない |

### 概観+詳細、ズーム、焦点+文脈

| 欄 | 内容 |
| --- | --- |
| 出典 | Cockburn, A., Karlson, A. & Bederson, B. B. (2008) A Review of Overview+Detail, Zooming, and Focus+Context Interfaces. *ACM Computing Surveys* 41(1)。著者公開版: https://www.microsoft.com/en-us/research/wp-content/uploads/2008/01/cockburn-ComputingSurveys09.pdf |
| 何を言っているか | 全体と部分を扱う手法は 4 つ: 概観+詳細（空間で分ける）、ズーム（時間で分ける）、焦点+文脈（1 つの表示に埋め込む）、手がかり（強調・抑制）。どれも理想ではない。概観+詳細は好まれ、文書の理解では上回るものが見つかっていないが、2 つの表示を結びつける手間と時間がかかり、動きのある作業では不利になりうる。ズームは前後の状態を結びつける負荷が大きく、遷移のアニメーションで大きく減る。歪みを使う焦点+文脈は、位置の判断と的の選択を損ないうる。詳細の変化は概観にすぐ映し、概観を見て回っても詳細は動かさないのが慣例 |
| 確からしさ | 多数の実験の系統的なレビュー。どれが最良かは課題しだいで、明確な指針は出せないと著者ら自身が書く |
| 当たるべき場面 | 枠の帯（全体）と選んだ枠の詳しい札（部分）の並べ方。複数のフレーズにわたる長い進行の見せ方。体験 B の計画（区間の役割）と各枠の候補の並べ方 |
| 判断の問い | 全体と部分を同時に見せる必要がある作業か、切り替えでよいか。2 つの表示を見比べる往復は、試聴や再生の速さに間に合うか。部分を変えたら、全体にすぐ映るか |
| 適切・不適切な例 | 適切: 詳しい札の下の変形を選ぶと、帯のカードの和音もすぐ変わる。不適切: 再生に合わせて、詳しい札が鳴っている枠のものに自動で切り替わり、読んでいた札が消える |
| chord-rambler との接点 | 画面 2 の帯と画面 3 の詳しい札（概観+詳細の一種。`docs/architecture/screen.md`）、`docs/product/concept.md` の 4 章の体験 A と B、8 章の画面の構成 |
| 確認日 | 2026-11-18 / 間隔 365 日（著者公開版の全文を開いた） |

### 記憶に頼らせない（作業記憶の小ささ、外部記憶、認識 > 想起）

| 欄 | 内容 |
| --- | --- |
| 出典 | Nielsen, J. (2009) Short-Term Memory and Web Usability, NN/g https://www.nngroup.com/articles/short-term-memory-and-web-usability/ 。Budiu, R. (2018) Working Memory and External Memory https://www.nngroup.com/articles/working-memory-external-memory/ 。Budiu, R. (2024) Memory Recognition and Recall in User Interfaces https://www.nngroup.com/articles/recognition-and-recall/ 。W3C WAI (2021) Making Content Usable for People with Cognitive and Learning Disabilities https://www.w3.org/TR/coga-usable/ 。Miller, G. A. (1956)、Cowan, N. (2001) |
| 何を言っているか | 見えなくなった情報を頭に保てる量は小さく（NN/g は約 7 チャンク、約 20 秒で薄れるとする）、作業記憶に障害のある人は 1〜3 個しか保てないことがある（COGA）。容量は人によって大きく違い、作る側は使う人の容量を大きく見積もりがち。だから保たせず、画面に出しておく（外部記憶。比べる表、とっておく仕組み）。手がかりのある認識は、手がかりのない想起より易しい。NN/g は「メニューは 7 個まで」を誤解だと書く。並んで見えているものは認識で選べるから |
| 確からしさ | NN/g の記事は、容量の小ささと個人差を前提に指針を述べる。数は記事の値で、Miller と Cowan の原論文は開いていない。COGA は W3C のノート（規範ではない）。**よくある誤用:** 7 を「並べてよい項目数の上限」に使う。当たるのは、見えなくなった情報を保たせる場面だけ |
| 当たるべき場面 | 前に試聴した候補と今の候補を比べさせる、前の枠の和音を覚えたまま次を選ばせる、和音名を記法で打たせる、のように「覚えておいて、あとで照合する」ことを求めていないかの点検 |
| 判断の問い | この操作で、使う人は見えないものを何個保たなければならないか。それを画面に出しておけば保たなくて済むか。この操作は、見えているものを選ぶ形か、記法や前の状態を思い出す形か |
| 適切・不適切な例 | 適切: 候補を試聴したあとも、比べた候補が一覧に並んだまま残り、試聴中の印だけが移る。不適切: 「候補は 4 個まで」と、見えている一覧の数に容量の数を当てはめる |
| chord-rambler との接点 | 末尾に足す候補と枠を埋める候補の比べ方、和音名の入力、変形の一覧、`docs/product/concept.md` の 2 章の 1（選んで学ぶ） |
| 確認日 | 2026-11-18 / 間隔 365 日（NN/g の 3 記事と W3C COGA を開いた。COGA は長く、頭の約 2 割だけを読んだ。Miller と Cowan の原論文は開いていない） |

### 行長と読みやすさ（WCAG 1.4.8）

| 欄 | 内容 |
| --- | --- |
| 出典 | W3C WCAG 2.2 SC 1.4.8 Visual Presentation (AAA) の Understanding https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html |
| 何を言っているか | 次を使う人が得られる仕組み（ブラウザでもよい）を求める: 文字と背景の色を選べる、1 行が 80 字以内（CJK は 40 字以内）、両端揃えにしない、行間が 1.5 倍以上、段落の間が行間の 1.5 倍以上、200% に拡大しても 1 行を読むのに横へスクロールしない。行が長いと次の行の頭に戻りにくい読者がいる。CJK の 1 字は欧文の約 2 字の幅に当たるので、上限を半分にしている |

| 判断の問い | 1 行の字数は 40 字以内か。短すぎて行替えが増えていないか。200% に拡大しても、横のスクロールなしに読めるか |

### 強調と手がかり（前注意的な特徴）

| 欄 | 内容 |
| --- | --- |
| 出典 | Laubheimer, P. (2017) Dashboards: Making Charts and Graphs Easier to Understand, NN/g https://www.nngroup.com/articles/dashboards-preattentive/ 。Treisman, A. & Gelade, G. (1980) A feature-integration theory of attention. *Cognitive Psychology* 12 |
| 何を言っているか | 長さ・面積・角度・2 次元の位置・色は、注意して探さなくても一瞬で知覚される（前注意的）。量は長さと位置で表すのが正確で、色は順序を持たないので量には使わない。カテゴリは形・まとまり・近接の方が色より確かで、色は 2 番目の手がかりとして重ねると効く。色の見え方が多くの人と違う人は、男性で約 8%、女性で約 0.5% |
| 確からしさ | NN/g の記事は、ダッシュボードのグラフについての実務の指針。前注意的な特徴の実験の原論文は開いていない |
| 当たるべき場面 | 鳴っている枠・試聴中の候補・選んだ枠を、文を読まずに一瞬で見つけさせたいとき。強調に使う特徴を決めるとき。印の種別（機能、解決、終止）を見分けさせたいとき |
| 判断の問い | 強調は、周りのどれとも違う特徴（位置、枠、明るさ、形）で浮き上がるか。色だけで区別していないか。同時に出る複数の強調（選んだ、鳴っている、試聴中）が、互いに違う特徴を使っているか |
| 適切・不適切な例 | 適切: 鳴っている枠に、文字（「鳴っています」）と破線の枠の 2 つを重ねる。不適切: 選んだ枠と鳴っている枠を、同じ色の濃さの違いだけで示す |

### 使える幅で配置を切り替える

| 欄 | 内容 |
| --- | --- |
| 出典 | Apple *Human Interface Guidelines* "Layout" https://developer.apple.com/design/human-interface-guidelines/layout 。Android Developers "Support different display sizes" https://developer.android.com/develop/ui/compose/layouts/adaptive/support-different-display-sizes |
| 何を言っているか | 配置は端末の種類や向きではなく、使える幅（と高さ）で決める。物理的な画面の値で決めない。幅が変わっても機能は変えず、見せる量と配置だけを変える。部品は、自分に与えられた幅で配置を変える。文字を大きくする設定に合わせ、横に並べたものを縦に積む、行を伸ばすなどして、切れや重なりを防ぐ。最大と最小の配置を先に試す |
| 確からしさ | プラットフォームの実務の指針。Web についての資料ではないが、考え方は同じく当てはまる |
| 当たるべき場面 | 幅で配置を変えるしきい値を決めるとき。狭い幅で区画を縦に積むか、横に並べるかを決めるとき |
| 判断の問い | 分岐の条件は使える幅か。狭い幅で、できること（試聴、枠を埋める、役割を置く）が失われていないか。文字を大きくしても崩れないか |

### 流れて消える情報（WCAG 2.2.1 / 2.2.2、自動で進む表示）

| 欄 | 内容 |
| --- | --- |
| 出典 | W3C WCAG 2.2 SC 2.2.1 Timing Adjustable (A) https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html 、SC 2.2.2 Pause, Stop, Hide (A) https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html 。Nielsen, J. (2013) Auto-Forwarding Carousels and Accordions Annoy Users and Reduce Visibility, NN/g https://www.nngroup.com/articles/auto-forwarding/ 。一過性情報効果: Leahy, W. & Sweller, J. (2011) *Applied Cognitive Psychology* 25(6) |
| 何を言っているか | 動く・流れる内容は、読む時間を区切る（2.2.1 の Understanding）。時間の制限は、切れる、既定の 10 倍以上に延ばせる、切れる前に知らせて簡単な操作で延ばせる、のどれかを満たす。使う人が操作できる限り、字幕のように他の内容と同期するものは 2.2.1 の対象外。5 秒で消える新着の知らせは、同じ情報を別の場所で得られるなら時間の制限に当たらない。2.2.2 は、自動で始まり、5 秒を超えて、他の内容と並んで動くものと、自動で更新されるものに、止める・隠す（または更新の頻度を変える）手段を求める。活動に欠かせないものは例外。リンクやボタンを押して始めたものは「自動で始まる」に当たらない。NN/g は、5 秒ごとに切り替わる箱で、使う人が「読む時間がなかった」と言い、いちばん大きな要素の中身を見落とした例を挙げ、切り替えは使う人が求めたときだけにせよと言う |
| 確からしさ | WCAG は規範（A）。NN/g の記事は 1 人の観察と専門家の分析。一過性情報効果の原論文は開いていない |
| 当たるべき場面 | 再生に合わせて、鳴っている枠の印や札を切り替えるとき。知らせの文を、時間で消すか、次の操作で消すかを決めるとき。再生中にだけ見える情報を足すとき |
| 判断の問い | この情報は、使う人が読み終える前に消えるか。消えるなら、同じ情報が戻って見られる場所に残っているか。自動で切り替わるものは、使う人が始めたものか、止められるか。知らせは時間ではなく操作で消えるか |
| 適切・不適切な例 | 適切: 鳴っている枠の印だけを再生に合わせて移し、各枠の和音名と札は帯に残す。枠を縮めた知らせは、次に進行を変える操作で消す。不適切: 再生中だけ、鳴っている枠の詳しい札を 1 拍ごとに差し替えて出し、止めると消える |
| chord-rambler との接点 | 鳴っている枠の印（「鳴っています」と破線の枠。`frontend/src/features/progression/usePlayer.ts` が時刻で移す）、帯の下の知らせの行（時間では消えない。`docs/architecture/screen.md` の「フレーズをまたがない」）、再生と試聴は使う人が押して始める |
| 確認日 | 2026-11-18 / 間隔 365 日（WCAG 2.2 Understanding 2.2.1 と 2.2.2、NN/g の記事を開いた。Leahy & Sweller の原論文は開いていない） |

### 既定値の力と、選択肢の数

| 欄 | 内容 |
| --- | --- |
| 出典 | Nielsen, J. (2005) The Power of Defaults, NN/g https://www.nngroup.com/articles/the-power-of-defaults/ 。Loranger, H. ### 応答時間のしきい値（0.1 / 1 / 10 秒）と進捗の示し方

| 欄 | 内容 |

| 欄 | 内容 |

### ライブリージョンと状態の知らせ（うるさい読み上げの危険）

| 欄 | 内容 |
| --- | --- |
| 出典 | W3C WCAG 2.2 SC 4.1.3 Status Messages (AA) https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html 。MDN "ARIA live regions" https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Guides/Live_regions 。W3C *WAI-ARIA 1.2* https://www.w3.org/TR/wai-aria-1.2/ |

# next-issue

次に着手する `ready` の Issue を、決まった規則で 1 つ選ぶ。規則と止まる条件の本体は、`docs/dev/workflow.md` の「次の Issue の選び方と、止まる条件」と ADR-0013 にある。ここは、その手順だけを書く。

GitHub の操作は、そのセッションで使える道具（GitHub の MCP のツール、または `gh`）で行う。

## 手順

1. **上限を見る。** 開いている PR のうち、head のブランチ名が `claude/` で始まるものを数える。3 本以上なら、その一覧（番号、題、閉じる Issue）を示し、マージか方針の判断を仰いで止まる。
2. **集める。** 開いている `ready` の Issue を全部集める。
3. **除く。** 次に当たるものを除く。
   - その Issue を閉じる PR が、すでに開いている（着手済み）。
   - 本文の「依存」に書いた Issue（`blocked by #N`）が、まだ開いている。
4. **並べる。** 残りを、`priority:high` のラベルが付いたものを先に、同じなら番号の小さい順に並べ、先頭の 1 つを選ぶ。
5. **選べないとき。** 残りがなければ、開いている `needs-decision` の Issue の一覧と、依存で止まっている `ready` の Issue の一覧（何を待っているか）を示して止まる。
6. **着手する。** 選んだ Issue と、どの規則で先頭になったか（例: 「`priority:high` はなく、番号が最も小さい」）を 1 行で示す。`docs/dev/workflow.md` の「1 スライスの進め方」で着手し、同じ 1 行を PR に書く。
7. **途中で判断が要ったら。** 実装を止め、要る判断を Issue のコメントに書いて止まる。判断を埋めない。

## 守ること

- 優先度を自分で判断しない。Issue の重要さを読んで順を変えない。
- `proposal` と `needs-decision` の Issue には着手しない。
- 1 セッションで 1 つだけ選ぶ。終わっても、次の Issue を続けて選ばない。
- ラベルを付け替えない。
- 所有者がその場で別の Issue を指示したら、指示に従い、規則ではなく指示で選んだことを PR に書く。

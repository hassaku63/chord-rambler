# standards

`index.md` は、chord-rambler で出会う業界標準の索引である。決定の理由は ADR-0015。

## 使い方

1. 決めようとしていることを 1 行で言う（例: 「Dockerfile で `COPY --exclude` を使う」）。
2. `index.md` の「当たるべき場面」の欄で、当たる項目を探す。
3. 見つかったら、仕様の中身は推測せず、その項目の一次情報を開いて確かめる。開けなければ、開けなかったことを PR か Issue に書き、推測で書かない。
4. 見直しの期限（確認日 + 間隔）を過ぎた項目を根拠に使うときは、先に一次情報を開き直す。確かめ直す手順は `docs/dev/knowledge-review.md`。
5. 見つからなければ、そう書いて進める。足すべき標準だと思ったら、観察の Issue にする（今の作業に混ぜない）。

## 書くもの・書かないもの

- 書く: 名前と発行元、何を決めているか、一次情報の URL と入手の条件、状態（現行か、後継があるか）、当たるべき場面、chord-rambler との接点、確認。
- 書かない: 仕様の本文や要約、例のコード、一次情報を開かずに書いた中身。
- chord-rambler の書き方が標準の勧めと食い違うときは、「接点」の欄に食い違いとして書く。直すかどうかは別の Issue にする。

## プラクティスの索引との分担

| 索引 | 中身 | 引く場面 |
| --- | --- | --- |
| `.claude/skills/practices/index.md` | 開発の知見（機械で検出できない判断） | 設計・実装・レビューで、テストや抽象や境界を決めるとき |
| `index.md`（この索引） | 業界標準と、その一次情報の場所 | ファイル形式・記法・プロトコル・設定ファイルの書き方を決めるとき |

## 項目の形

項目は `###` の見出しと、次の欄を持つ表。節（`##`）は分野ごとに分ける。

| 欄 | 書き方 |
| --- | --- |
| 発行元 | 標準を決めている組織やプロジェクト |
| 何を決めているか | 1〜2 行 |
| 一次情報 | URL と、入手の条件（登録の要否、有償か） |
| 状態 | 現行か、後継があるか。確かめた時点の版 |
| 当たるべき場面 | どの判断のときに引くか |
| chord-rambler との接点 | 関係するファイル、ADR、検査。食い違いがあれば、それも |
| 確認 | `YYYY-MM-DD / 間隔 N 日`。一次情報を実際に開いた日と、見直しの間隔 |
